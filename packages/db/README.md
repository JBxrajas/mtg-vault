# packages/db

Drizzle ORM schema and migrations for Postgres (Neon in production).

## Tables

| Table | Purpose | Key |
|---|---|---|
| `sets` | Editions | Scryfall set id |
| `cards` | Oracle cards (the card as a concept) | Scryfall `oracle_id` |
| `printings` | A card in a specific set | Scryfall card id; unique per set, collector number and language |
| `price_snapshots` | Daily price of a printing (USD, EUR, TIX; foil and etched) | `(printing_id, captured_on)` |

`cards.name` has a trigram GIN index (`pg_trgm`) for fuzzy name search. The migration creates the extension.

### Users, collection and decks

| Table | Purpose | Key |
|---|---|---|
| `user`, `session`, `account`, `verification` | Better Auth (username and password); generated in `src/auth-schema.ts` | text ids |
| `collections` | A user's single collection | `user_id` unique |
| `collection_items` | Inventory stacks: printing, finish, condition, language, quantity, purchase data | unique `(collection, printing, finish, condition, language)` |
| `binders` | Named sub-collections | unique `(collection, name)` |
| `binder_items` | Copies of a stack held in a binder | `(binder, collection_item)` |
| `decks` | A user's decks: name, format, visibility | uuid |
| `deck_cards` | Oracle cards in a deck, per board | `(deck, oracle_id, board)` |

Quantities are checked to be positive. Deleting a user cascades. The "copies across binders do not exceed the stack" rule and deck format rules belong to the API. See [ADR 0008](../../docs/adr/0008-users-collection-binders-decks.md). `src/auth-schema.ts` is generated by Better Auth's CLI; regenerate it instead of editing by hand.

## Commands

```bash
pnpm --filter @mtg-vault/db generate        # create a migration after editing src/schema.ts
DATABASE_URL=postgres://... pnpm --filter @mtg-vault/db migrate   # apply migrations
```

`drizzle-kit generate` needs no database. `migrate` needs `DATABASE_URL`.

Migrations in `migrations/` are committed. `0000_init.sql` was edited by hand to add `CREATE EXTENSION IF NOT EXISTS pg_trgm;` at the top, because the GIN index depends on it; keep that line if the file is ever regenerated.

## Status

Migrations `0000_init`, `0001` (widens `cards.cmc` to `numeric(10,1)`) and `0002` (users, collection, binders, decks) are applied to the Neon `production` branch (2026-11-04), and the catalog tables were filled by the Scryfall import ([apps/jobs](../../apps/jobs/README.md)).

Before `0002` reached production it was verified on a throwaway Neon branch, since deleted: unique and check constraints reject duplicates, a second collection and zero quantities, and deleting a user cascades. The new tables are empty until the API writes to them.

Apply future migrations with `DATABASE_URL=<unpooled url> pnpm --filter @mtg-vault/db migrate`; `drizzle-kit` reads `DATABASE_URL`, so pass the unpooled value there.
